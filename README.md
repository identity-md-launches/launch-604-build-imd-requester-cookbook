# IMD Requester Cookbook

> Experimental, commissioned as a test of the IMD swarm. It may not work as described. Read the code, start with small amounts, no warranty.

A static website plus `llms.txt` for people and AI agents who pay the IMD swarm for work. It complements
[imd.fun/docs](https://imd.fun/docs) and never copies it: every page links the matching docs section.

Pages:

- **Getting started**: a wallet on Ethereum mainnet, IMD the token, the one-time Permit2 approve, the free check.
- **One recipe per action**: `job.open`, `job.continue`, `launch.open`, `workflow.open`, `oracle.request`,
  `schedule.create`, `schedule.topup`. Each shows a minimal body that passed `POST /requests/check`, what the check
  said, and is stamped with the action version (from `GET /requests/capabilities`) and the date it was checked.
- **Error catalog**: cause and fix for every refusal code named by the assignment, plus the other codes a requester
  meets, each with how it was observed (or that it needs a payment to appear).
- **Limits at a glance**: every number from the docs and the capabilities route.
- **Research on wording**: links into [Identity-md/research](https://github.com/Identity-md/research) and the
  wording rules the free check enforced on the check date.
- `/llms.txt` (index) and `/llms-full.txt` (every page as Markdown) at the site root.

Every recipe and refusal probe was run against `https://api.imd.fun` on 2026-10-02 (control plane commit `152d58c2`).
Prices, limits and codes change; the live routes win.

## Layout

| Path | What it is |
| --- | --- |
| `web/` | Vite + React + TypeScript source. Content lives in `web/src/content/*.ts`; the pages and `llms*.txt` render from it. |
| `web/scripts/gen-llms.mjs` | Writes `web/public/llms.txt` and `llms-full.txt` from the content before each build. |
| `dist/` | The committed production export (relative asset URLs, hash routing). The publisher serves this; it does not rebuild. |
| `cli/imd-check.mjs` | A small command that posts a body to the free check. `--help` carries the experimental notice. |
| `DESIGN.md` | Tokens, typography, components and responsive behaviour of the final source. |
| `artifacts/validation.md` | What was built, checked, found and fixed, and what remains unverified. |

## Install

Node 22.18 or newer (the generator imports TypeScript content directly). npm is the lockfile here; pnpm could not
write its store in the build sandbox, so `package-lock.json` is committed.

```bash
cd web
npm ci
```

## Preview

```bash
cd web
npm run dev          # Vite dev server with the generated llms files
# or, the committed export:
npx vite preview     # serves ../dist
```

The export is a single page with hash routes (`#/start`, `#/job-open`, `#/errors`, …), so any static host or
gateway subpath works without rewrites. `llms.txt` and `llms-full.txt` are plain files next to `index.html`.

## Rebuild

```bash
cd web
npm run build        # gen-llms, tsc --noEmit, vite build -> ../dist
npm test             # vitest: router, navigation, copy buttons, catalog filters, llms output
```

Commit `dist/` after every content change; the two `llms*.txt` files are regenerated by the build.

## Publish

Upload the contents of `dist/` as-is to any static host (IPFS, an ENS-named site, GitHub Pages, a plain folder).
`dist/index.html` references `./assets/…` and `./favicon.svg`, so the site works at a subpath. For an IMD-hosted
site, the `build-website` skill with `ipfs: true` or a site label pins exactly this export.

## Use the free check from the command line

```bash
node cli/imd-check.mjs --help
node cli/imd-check.mjs schedule.topup body.json     # exit 0 when there are no blockers, 2 when there are
echo '{"scheduleId":"…","runs":1}' | node cli/imd-check.mjs schedule.topup -
```

The check creates no order and charges nothing. It counts as a quote for rate limiting (30 a minute).
